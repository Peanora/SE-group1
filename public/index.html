如何使用需求编排台
  1. 导入软件需求。上传 Markdown、TXT、Word，或直接粘贴正文。首次体验可以载入工单系统示例。
  2. 开始编排。本地规则模式无需密钥，按文档结构提取需求并生成计划。模型模式需在服务端配置。
  3. 观察执行。点击流程节点查看依赖、状态与日志；可在阶段边界暂停，或在运行失败后重试失败节点。
  4. 确认规格。核对需求和验收条件，逐项回答待确认问题并保存修订。确认规格后，编排器才生成架构和开发计划。
  5. 确认开发计划。核对任务、依赖和需求来源；修改后保存并重新确认。退回修改须填写意见。确认计划后导出 Markdown 文档包。
工作流节点表示规划文档的生成过程。“开发任务”是交给开发者或编码工具继续执行的计划，这一版不会自动写入目标项目的代码。
规划模式
本地规则模式适合结构清晰的需求，结果需要人工审阅。要启用模型模式，可在项目 .env 配置 LLM_BASE_URL、LLM_MODEL 和 LLM_API_KEY，再重启服务。密钥只留在服务端。
