设计规格—任务分解—开发编排及执行可视化与交互

本流程以已确认需求为起点，由小组与 AI Agent 共同完成设计、任务拆分和软件开发。编排器组织主 Agent 编码、测试子 Agent 验证和 Review 子 Agent 审查，并根据结果安排返工或进入后续任务。小组确认关键设计，处理争议和需要人工判断的问题。

## 一 设计规格

将已确认需求、项目边界和已有资料提供给规格 Agent，生成设计初稿，说明软件要完成什么、包含哪些模块、各模块的输入输出及验收条件。

围绕初稿共同讨论功能规则、接口、异常处理及需要人工确认的位置。对不清楚的内容提出问题，由 Agent 补充说明或给出备选做法，再由小组决定是否采纳。涉及需求变化时，先更新并确认需求，再修改设计。

修改后检查设计是否覆盖核心需求、模块之间能否衔接，确认无关键遗漏后形成设计规格，进入任务分解。

产出：经过确认的设计规格。

## 二 任务分解

将设计规格交给规划 Agent，拆成具体开发任务。每项任务写清目标、输入资料、代码或功能范围、预期产出和验收条件，并关联对应规格。任务粒度应便于独立编码、测试和审查。

整理任务依赖，说明哪些必须先完成、哪些可以并行、哪些需要等待人工决定。检查接口和共享代码是否会冲突，开发环境与所需工具是否具备，避免把相互依赖的任务直接同时开工。

沿完整开发流程共同检查，发现遗漏就修改任务；涉及设计问题则返回设计规格。任务、依赖及验收条件确认后，交给编排器组织开发。

产出：开发任务清单、依赖关系及验收条件。

## 三 编排器组织开发与验证

执行流程：领取就绪任务 → 主 Agent 编码并自检 → 固定代码版本 → 测试与 Review 子 Agent 独立检查 → 汇总结果 → 不通过则修复并复验，通过则完成当前任务。相关任务完成后再进行集成验证。

主 Agent 开发：编排器将满足依赖的任务、设计规格、相关代码及验收条件交给主 Agent。主 Agent 完成编码后先检查构建、启动和已有基础测试，修复明显错误，再固定本轮代码版本，交给两个子 Agent 检查。

独立测试与审查：测试子 Agent 依据需求和验收条件验证正常、异常及边界行为，保存测试用例、结果和失败复现信息。Review 子 Agent 结合设计与代码上下文，主动查找逻辑漏洞、规则遗漏、接口不一致及潜在回归，注明问题位置、影响和依据。两者可以并行，必须检查同一版本；检查期间主 Agent 不修改该版本，测试环境与审查目录应避免相互干扰。

汇总与返工：编排器收集两方结果，主 Agent 核实问题并修复；对不采纳的意见说明理由，有争议时交小组判断。修复后形成新版本，再次触发测试和 Review，验证原问题已解决且未引入新问题。新增测试纳入后续回归，每项通过结论均记录对应代码版本。

通过与升级：当前任务的验收条件达成、必要测试通过、阻塞性审查问题关闭后，才可标记完成并释放下游任务。相关任务合并后进行集成验证，最终交付前运行完整的必要检查。同类问题反复出现、需求含糊或超过预设返工轮次时，暂停循环交人工判断，必要时返回设计或任务分解。

执行可视化：展示任务依赖、当前开发阶段、主 Agent 与子 Agent 状态、代码版本、测试及 Review 结果、问题处理和返工轮次。点击任务可查看代码变更、失败证据与历史记录，界面与实际执行状态保持一致。

执行交互：提供启动、暂停、继续、查看问题、重新检查及人工处理争议等操作。暂停时停止派发新一轮工作，在途工作结束后保存结果；继续时从记录的阶段恢复。人工确认记录依据，不能直接将失败测试或未解决的阻塞问题标为通过。

产出：通过验证的代码、测试与 Review 记录、返工记录，以及最终集成验证结果。
