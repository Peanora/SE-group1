# 可复现验收流程

本文件说明如何用同一条命令重复验证 Taskflow 的需求规划闭环，并在提供固定参考交付包时复核固定 Web 软件。它不依赖真实模型，不使用用户 `data/`。

## 一条命令

```powershell
npm run acceptance
```

默认使用 `examples/library-system.md`，在临时数据目录创建项目，以本地规则模式执行两次：

1. 创建需求快照；
2. 生成规格；
3. 自动填写示例中的待确认问题并保存修订；
4. 确认规格；
5. 生成架构、开发任务和检查报告；
6. 确认计划并导出文档包；
7. 校验下载 ZIP 的文件清单、文档哈希、计划投影哈希和模型调用次数。

默认两次都完成后比较：

- `spec.md`、`architecture.md`、`task.md`、`review.md`、`handoff.md`、`requirements.md` 的哈希是否一致；
- 去掉运行编号和确认时间后的 `plan.json` 投影哈希是否一致；
- 两次运行是否都是 local 模式且模型调用为 0。

结果写入 `output/acceptance-<时间>/`：

| 文件 | 内容 |
| --- | --- |
| `acceptance.json` | 完整机器可读报告，包含版本、输入哈希、两次运行、每项检查和 ZIP 哈希 |
| `acceptance.md` | 适合验收时展示的中文摘要 |
| `run-1.zip`、`run-2.zip` | 两次实际下载的规划文档包 |

## 可选：固定参考 Web 交付复核

提供一份**与当前代码规则兼容**的固定图书借阅源码 ZIP 后：

```powershell
npm run acceptance -- --archive output/live-web-delivery-3lVPQC/library-web-source.zip
```

该步骤不调用模型，只在干净副本重新执行固定 HTTP/数据库检查和真实 Edge 浏览器检查。它要求本机有可用的 Windows MXC 和 Microsoft Edge；不把包内旧 Review 或历史“通过”声明当作本次结论。旧规则生成的包会被明确拒绝，需使用当前规则重新生成的交付包。

不提供 `--archive` 时报告状态为 `planning_passed_only`，表示规划闭环已通过，但固定 Web 交付未复核；不会把不完整验收写成 `passed`。

## 常用选项

```text
--fixture <路径>      指定验收需求，默认 examples/library-system.md
--out <目录>          报告和文档包输出目录
--repetitions <2>     规划重复次数，1-3，默认2
--archive <路径>      可选固定参考Web源码ZIP
```

## 手工界面验收

需要展示工作台交互时，可以按同一流程在网页操作：

1. 新建项目，载入 `examples/library-system.md`，选择“本地规则模式”；
2. 启动编排，等待“等待规格确认”；
3. 回答页面列出的待确认问题，保存修订；
4. 确认规格；
5. 核对架构、任务和检查报告；
6. 确认计划并导出，下载文档包。

这条手工流程不调用模型，因此不受模型输出波动影响。自动验收脚本中的确认是为了可重复性，**不替代真实用户审阅**；报告中会明确标注这是自动验收。

## 可复现的边界

- 需求文件、代码版本、Node.js 版本和验收规则固定后，本地规划的文档哈希和计划投影哈希应保持一致。
- ZIP 中包含运行编号和确认时间，因此 ZIP 整体哈希不要求跨运行相同；报告比较的是文档哈希和去时序后的计划投影。
- 固定参考 Web 交付复核依赖本机 MXC/Edge 和当前兼容交付包；缺少环境时失败会写明原因，不跳过为通过。
- 规划导出或固定参考 Web 检查都不代表任意上传业务已完成编码或验收。
