# Taskflow 全站前端重写

基线 `ecae414`。目标是在同一版本交付项目工作台、两类模型设置、团队账号和 Factory 外壳的新前端。现有 API 与本地数据负责项目、运行、角色权限和同版本验收。

项目首页优先显示当前运行、待处理动作和阶段脉络。任务图及证据详情按窄屏和桌面分别排布。全站使用墨绿、浅暖灰和纸白，暖橙表示待处理，砖红表示失败；标题使用系统无衬线，运行编号和提交使用等宽字。参考 ThinkRail 的项目与证据并置、Paperclip 的待处理入口和 Kestra 的逐次运行详情。

工作台、任务画布、设置、团队及 Factory 各有唯一写入责任。React + TypeScript + Vite 构建同源静态入口，业务面板逐个接入已有状态和操作。验收使用已有本地不收费夹具，检查项目/运行切换、确认计划到验收准备、需求保存、设置、团队权限、Factory 外壳以及窄屏。

## 实现与集成

- 项目工作台以当前运行和下一步为入口，组织规划、任务、需求与功能、代码与验收。阶段详情、项目导航、进度和执行记录由 React 渲染。深层审批与编辑继续使用已有业务控制器及版本校验。
- React Flow 映射服务端任务依赖和候选证据。桌面保持横向布局，窄屏顺序向下。原生滚动、缩放、焦点及独立兼容路径沿用现有契约。
- API 服务、Agent 角色、团队和 Factory 外壳重写为 React 页面。每组入口只加载自己的样式，以免全局滚动规则影响设置抽屉。初次加载时导航在项目就绪后开启。
- Vite 产物写入本地忽略的 public/ui。npm start 自动构建。服务端同源 API、数据目录、团队权限和 Factory 原生执行边界沿用原契约。

## 浅色工作台重构与功能补齐

以 `c2c525a` 为基线。以用户给出的 SE-TeamPrjoect 浅色工作站为视觉参照，使用紧凑横向导航、白色内容、细边线与横向工作区。Taskflow 项目层放在顶部，中央工作面先呈现当前审批或证据，侧栏集中呈现运行阶段、待办和控制操作。界面使用纸白 #ffffff、浅雾 #f8fafc、墨蓝 #182342、靛蓝 #3846ce、边线 #d5ddf0 和琥珀 #a96a18。正文使用系统无衬线，项目名使用宋体标题，编号和版本使用等宽字体。

实现开发任务清单、运行历史直达和已确认的流程缺口，数据与操作使用 Taskflow 自己的真实 API。检查需求换版、规格与计划确认、开发视图、验收和交付权限在新布局中完整可达。设置、团队与 Factory 采用同一交互方向，真实 Edge 检查桌面和 390px。

- 正式布局采用顶部导航、左侧运行栏、中间工作面、右侧节点检查。导航入口移除了旧 styles.css 和 workbench-theme.css，需求和验收证据采用独立的新布局。参考该仓库的浅色分栏。[视觉参考](https://github.com/ycwang-April/SE-TeamPrjoect)
- 计划清单读取当前计划、草稿或模拟任务状态，任务选择与画布共享。回程可定位指定项目、运行及工作区，390px 顺序叠放。
- 本机负责人可以在研发派发前停止自动交付推进。状态与请求时间保存到运行，重启后核对在途证据。回执待核对时保留未知用量。
- 开发模式的本地展示使用临时数据。测试中用实际 API 和本机模型夹具审查停止、重启和权限边界。本轮没有数据库迁移。

最终相关回归 85 项，83 通过、0 失败、2 跳过。项目栏调整后的历史、清单和团队长账号复查 3/3。自动推进停止同时通过 HTTP 和真实 Edge 的在途规格测试。已打开 4323 独立工作站以便直接验收。

## 独立交付工作站

基线 `9eea9a2`。Edge 实机定位到「代码与验收」默认打开辅助工具，旧的运行表单占据主区。本轮验收入口为 `/?view=execution`。选择等待计划确认的演示运行，应直接看见当前卡点、当前需求至候选的版本链、检查结果和回到规划的操作。

- 总览、验收清单、候选证据、本机版本与参考实验独立切换。阶段和错误通知可直达对应记录。
- 清单编辑区显示定义、审阅依据和记录侧栏。本机版本显示已核对的当前版本与历史，分开备份、迁移与继续开发。固定参考执行按许可逐步展示启动、预算、运行和结果。
- 已有候选先显示当前提交和同版检查。启动、修复和费用设置可在对应操作中展开，390px 的候选历史按记录显示各项检查。
- 候选、费用及源码下载使用现有服务端状态和版本绑定。验证使用独立演示数据与模拟模型夹具。

实测及本地截图见[验证记录](../VERIFICATION.md#2026-11-25-独立交付工作站)。
