# Taskflow 全站前端重写

基线 `ecae414`。目标是在同一版本交付项目工作台、两类模型设置、团队账号和 Factory 外壳的新前端。现有 API 与本地数据负责项目、运行、角色权限和同版本验收。

项目首页优先显示当前运行、待处理动作和阶段脉络。任务图及证据详情按窄屏和桌面分别排布。全站使用墨绿、浅暖灰和纸白，暖橙表示待处理，砖红表示失败；标题使用系统无衬线，运行编号和提交使用等宽字。参考 ThinkRail 的项目与证据并置、Paperclip 的待处理入口和 Kestra 的逐次运行详情。

工作台、任务画布、设置、团队及 Factory 各有唯一写入责任。React + TypeScript + Vite 构建同源静态入口，业务面板逐个接入已有状态和操作。验收使用已有本地不收费夹具，检查项目/运行切换、确认计划到验收准备、需求保存、设置、团队权限、Factory 外壳以及窄屏。

## 实现与集成

- 项目工作台以当前运行和下一步为入口，组织规划、任务、需求与功能、代码与验收。阶段详情、项目导航、进度和执行记录由 React 渲染。深层审批与编辑继续使用已有业务控制器及版本校验。
- React Flow 映射服务端任务依赖和候选证据。桌面保持横向布局，窄屏顺序向下。原生滚动、缩放、焦点及独立兼容路径沿用现有契约。
- API 服务、Agent 角色、团队和 Factory 外壳重写为 React 页面。每组入口只加载自己的样式，以免全局滚动规则影响设置抽屉。初次加载时导航在项目就绪后开启。
- Vite 产物写入本地忽略的 public/ui。npm start 自动构建。服务端同源 API、数据目录、团队权限和 Factory 原生执行边界沿用原契约。
