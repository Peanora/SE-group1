# 模糊需求澄清闭环
基准：dde2edc，独立分支codex/requirement-clarification，默认服务保持原版本。
目标：合法空需求+非空问题进入待澄清，答复后显式发起预算内规格请求；引用允许原文和保存的答复，原始快照不改。新规格和计划仍需双确认。
范围：解析、审阅门禁、动作、问题表单、契约和回归；不调用真实模型，不自动重试用户旧失败运行。
验收：问题/回答可保存刷新，回答后继续；未答/过期/重复/超预算拒绝，失败/重启可追溯，原快照不变，下游不得提前执行。模拟HTTP及Edge桌面/窄屏验证。

实现：planning-review生成合成上下文及独立引用白名单；planner接受“空需求+问题”并标记clarificationRequired。clarify_spec要求当前版本、全答复和原预算，先保存历史再重新调度；新规格包含服务端重建的sourceClarifications。模型请求及私有回执复核绑定inputRevision，不改变sourceRevision。前端解释缺失信息、保存/调用区别和剩余次数，展示补充历史；原规划和固定参考门禁保留。
