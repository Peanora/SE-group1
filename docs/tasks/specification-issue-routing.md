# 议题提案、交叉质疑与问题分流

基线 `6010b4a`。范围为手动多 Agent 规格评审、角色适配、版本回执、问题分流界面和定向回归。

1. 独立提案阶段为同一业务议题给各相关角色固定共同输入。保留来源，第一轮意见互不可见。
2. 稿件固定后，交叉质疑按同一议题向审阅角色提供其他席位的提案。每条质疑关联提案、当前版本和可复核条件。
3. 汇总时归并问题。局部缺项交规格主笔或已有规格修订入口，跨条款冲突列出受影响条款，缺少业务依据的取舍进入现有人工裁决。存在修订项时仍可处理已有的人工裁决，继续阻止未关闭规格进入工程规划。
4. 工单样例用于验收。旧轮次只读证据与原版本门禁兼容。真实模型链路使用本机 HTTP 替身验证。可视化方案以独立交互稿呈现。

验收包括同议题的角色信息隔离、固定同版的交叉质疑、三类路由、普通确认无法绕过、历史记录重读和桌面/窄屏操作。

## 验收结果

已实现为协议 v3。复用项目锁、版本、人工裁决和规格编辑接口。回执迟到时可处理已汇总的合法人工议题。若下一轮漏报旧阻塞，系统仍携带旧轮次和规格版本。草案和客户端不能写入裁决记录。

工单 F03 的问题定位到验收条件。现有原文足以判断项目外分派应该被拒绝，分流记录同时带原文及数据保持的复核条件。用户可跳到规格验收字段修订。已收集的同版回执可在重试使用，换版仍以新一轮全量复核作为当前保障。

`npm run check` 通过，`npm run spec-review:test` 186 项通过。隔离场景用本机真实 HTTP 工作台与 Edge 操作。三个视觉方案为独立预览，展示同一议题的流程、去向和证据三种阅读路径。[详细证据](../VERIFICATION.md)
