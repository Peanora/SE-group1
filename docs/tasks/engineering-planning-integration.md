# F02 工程设计接入记录

基准：8413772；独立工程组件依赖：e99df1b（本树依赖提交 8a76893）。本轮只接入规划器，不接编码、测试模型、执行服务或前端。

## 最小契约

- 仅新版模型运行在当前规格获人工确认后请求工程草案。架构与任务阶段共享同一次有界调用及其失败；本地规则与旧版运行保持原流程。模型错误不回落规则。
- `engineeringPlan` 保存经纯校验的完整草案；其版本、需求与角色来自当前规格。架构文档和待开发 DevTask 来自同一草案，保留可写文件、输入、输出与验收。结构覆盖不证明业务语义充分。
- 计划哈希在存在工程草案时额外绑定草案实际内容；无草案记录保持旧公式。规格修订归档旧草案并使缓存失效；人工计划修订保持原接口/实体/页面与全图可写文件集合，重验工程任务图后同步两种表示。
- `engineeringHistory` 只保存尝试编号、版本、状态、模型、未知或已知用量、结束枚举及回执摘要。不保存正文、配置、绝对路径。原始四字段回执仅以独占文件写入 store.directory 下 `.private/engineering-receipts`；不进入公开文档或 run 数据。
- 默认每个运行最多 3 次工程适配器调用，单次 60 秒（可信构造选项可调整，最高 120 秒、20 次）。`engineeringCalls` 是调度端适配器尝试预留，配置失败也不退还，不等于已证实的供应商收费请求数；回执与 usage 才提供已收到的模型证据。这是工程规划预算，不是平台全部模型用量。未知用量保留 null；模型已返回但回执落盘失败仍保留已知用量。重试新增历史；服务关闭取消等待，迟到/旧版本结果不能发布。暂停仍在阶段边界生效。
- 工厂和预算只由可信构造代码注入，HTTP 不接收函数、回执路径或凭据。进程内回调不是候选隔离或跨进程认证。

## 验收与范围

普通测试使用完整模拟传输，无真实模型/API、无用户数据。验证规格门禁、双分支单次调用、失败/预算/重试历史、取消迟到、暂停、旧版本、人工修订与私有导出边界；同时运行既有规划测试与相关语法检查。固定提交后由独立 Agent 复验；产品集成及真实模型验证由 root 后续执行。
