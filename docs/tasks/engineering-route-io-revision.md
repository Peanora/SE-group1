# 工程接口请求与响应的人工修订

新库存方案结构通过，独立语义审阅已发现登录及会话接口错误地把确认规格的 `{user:{id,roles,site}}` 包在 `item` 中。当前计划只能修任务与接口角色，不能保存这个明确的合同修正。保留已经生成的工程方案和三次调用历史，避免为了更正两处文字重跑规格与工程。

负责人可在当前待确认计划中修订现有接口的请求及响应描述，并与同一接口草稿的角色变更一次保存。沿用现有权限、撤权复核、版本、锁和结构校验。接口身份、方法、路径、错误结构、需求归属及文件范围由原计划提供。变更后生成新版本，重新运行计划检查并另行确认。新能力置于独立模块，已有工程对齐校验文件保持原字节，避免仅因新增编辑入口使其它运行的批准定义变更。

验证真实HTTP及实际页面，覆盖新格式保存、版本过期、陌生接口和未知字段、空文字及未授权角色拒绝。实际库存方案仍须对已确认规格重新独立核对，原语义失败保留。

作者相关回归63/63通过，耗时27926.749ms，包含真实 HTTP 及桌面和390px Edge。用同一操作合并请求、响应和角色修订，确认旧计划审批失效，又能确认新计划并导出。旧角色操作、撤权复核、只读角色、草稿刷新保留和验收计划回归均在此批覆盖。证据在 `output/engineering-route-io/author.tap`。冻结后另做独立Test/Review。
