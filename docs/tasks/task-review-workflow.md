# 开发任务的 Review 编排

基线为 `b8c303e`。在任务编排的主画布上，读者应能找到每个模块的代码 Review，解释通过和返工分别通往哪里，并从当前任务定位到对应候选的检查证据。

参考项目使用阶段框、不同类型的节点和带方向的条件边呈现编排。此处按项目已有的功能板块与依赖绘图。每个模块的 Review 对应本项目已有的独立代码审查，跨模块依赖仍由已确认计划约束。[参考画布源码](https://github.com/ycwang-April/SE-TeamPrjoect/blob/472cd7a5891a1a1bd22247a53197c78dc637d452/workflow-orchestrator/renderer/src/components/TwinGraphCanvas.tsx)

编码和自检后固定候选。独立 HTTP 与 Edge 验证通过后，Review 检查同一提交。有效阻塞意见进入该候选的审查记录，修复产生的新候选须重新测试与审查。只有已验收并集成的模块才满足后继任务的前置条件，汇合点等待全部直接前置。计划、模拟与执行记录在画布中分别标明。

## 编码任务画布

本轮基于 `525bf42` 接入已确认的交互预览。验收目标是在工作台打开任一真实计划，默认只看到编码卡，点开任一模块能查看该模块的同版验收与返工路径。拖动只调整视图坐标，连线随节点移动。方向动效保留静态底线与箭头，并响应系统减少动态效果设置。

本轮验证使用 `npm run ui:build`、`npm run check` 及任务图、审查、模拟调度和规划修订的 9 个定向测试文件。56 项通过。Edge 验证了默认收起、按任务展开、拖动连线、光段位置变化、减少动态效果、缩放小地图和编辑计划。使用校园预约需求生成的规划，在浏览器中核对了 3 个功能板块、6 张编码卡及 6 条依赖。示例运行采用本地规划，审查状态回归使用隔离的按任务候选记录。

## 初版 Review 入口的验收记录

- `npm run ui:build` 与 `npm run check` 通过，包含 TypeScript 和 311 个脚本语法检查。
- 任务工作流、审查投影及相关浏览器回归共 71 项通过。使用两个并行任务的离线执行记录，在真实 Edge 操作 Review 节点，验证当前任务、尝试和提交的归属，发现阻塞后的返工路径，换版后的复验，以及集成前后后继任务的状态。
- 在 1440px 和 390px 的校园场地预约样例中，6 个模块分别有可操作的 Review 节点。键盘和触屏可以定位所选任务的详情。另在 320px 检查画布边界，并复验编辑连线、上下换位和键盘操作。
- 本次未进行付费模型端到端交付或全仓测试。样例使用本地规划，运行中及返工状态用可重复的测试记录验证。
