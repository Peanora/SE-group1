# 网页配置多角色 Agent 与 API

基准：`631e2e055ff9a9400035e981908fbaf41f901b30`，分支 `codex/workspace-ui`。原有 `docs/tasks/team-delivery-plan.md` 未提交修改属于用户，本轮保留。

## 目标与范围

参考本机 am-workflow 的供应商、模型与角色绑定方式，增加网页配置多个 Chat Completions 兼容服务，并将规格、工程规划、测试提案、编码、审查五个实际角色接入各自服务。沿用既有角色职责、提示词、审批、预算和同版本验收；配置服务不代表软件通过验收，也不增加任意 Shell 或公网部署能力。

配置保存与应用均由本机后端处理。密钥不回传、不进入浏览器持久存储或导出包。本地私有配置重启可用，旧环境变量仍是默认配置。每个模型请求取独立快照，编码/审查整个执行冻结双路配置；旧 Worker 恢复须核对原配置版本，禁止静默换模型继续旧作业。

## 修改责任

- 配置存储 Agent：`lib/agent-settings.mjs`、存储回归。
- 调用链 Agent：规划/测试提案适配器、执行服务、Worker 白名单和路由回归。
- 页面 Agent：独立配置页及桌面/窄屏交互回归。
- 主 Agent：服务入口与权限、规划包装、集成、文档和最终提交。

## 验收

临时数据验证多服务 CRUD、角色绑定、密钥保留与清除、版本冲突、重启回读、非法配置拒绝；本机模拟 HTTP 服务验证真实角色请求到达对应模型，编码与审查配置各自冻结；接口拒绝跨源、非本机和非负责人访问；真实 Edge 检查桌面与 390px 页面、键盘焦点、错误后的草稿保留和控制台。普通验证不调用付费服务。完成后补实际结果与限制。

## 实现与数据流

配置页整体提交版本、服务与角色绑定 → 本机负责人接口检查 → 私有配置 CAS 加密保存 → 规划包装器或服务的可信配置回调 → 每请求/每执行冻结原生适配器配置。Worker 白名单增加可选 Review 配置，通过匿名 stdin 交接；公开配置指纹排除双路密钥。规划执行与固定参考的付费准入同时绑定编码/Review 公开设置，模型变更使旧确认失效，旧验收记录保留原验证版本。执行确认区显示两角色各自模型。
