# 同候选版本的独立测试与Review门禁

日期：2026年11月14日。基准：`05cd2a0`，开始时工作区干净。

## 目标和范围

在现有固定图书借阅任务上接入产品可调用的独立测试服务和Review模型适配器。两方独立读取同一固定候选代码；测试不继承编码自检结果，Review不读取测试结论。只有固定检查通过、Review完成且阻塞问题关闭，才发布任务验收通过。修复后生成新候选，两方都重新检查，旧结果保留且不能放行新版本。

保留原规划HTTP/前端及受控执行基础；本轮不扩展任意仓库、全栈生成、多Worker调度或公网发布。固定测试服务不是自主生成测试的模型Agent，验收通过仅限当前固定任务。

## 修改边界与最小契约

- 主Agent负责候选快照、门禁状态、执行器/命令入口集成及文档；独立工作区实现Review模型适配器，约定接口后串行集成。
- 绑定任务/尝试、规格/计划、候选提交、源文件哈希、验证清单及Review规则版本。每次检查另有唯一标识。
- 测试与Review使用不同快照目录；候选代码运行仍受MXC约束。检查前后核对原候选及快照，变化或取消即拒绝发布有效通过。
- Review只返回结构化意见，不能修改代码/测试/状态。缺失或错误响应不得当作无问题；阻塞问题复验需要明确结论。
- 总时长、编码/Review调用及输出共享受限预算。取消、服务错误和停止未确认保留原因及已完成的独立证据。

## 验收

1. 同一候选有实际独立测试执行及独立Review记录，门禁可核验。
2. 一方缺失/失败、阻塞意见未解决、版本不匹配、迟到或取消结果均不得通过。
3. 修复产生新提交，新候选重新检查两方，旧通过不继承；失败历史保留。
4. 普通测试不使用付费模型；真实MXC和必要的最小真实模型集成另外记录。
5. 主Agent自检后固定提交，独立测试与Review子Agent检查同一版本；修复后新版本复验。

## 实际验证

主Agent自检：`npm run check`31个脚本通过；显式启用真实MXC的`npm test`85/85通过、无失败/跳过。普通模式不请求付费模型，三个真实MXC测试仅在显式启用时运行。

真实命令联调：`npm run execution:check -- --model`使用1次编码和1次独立Review请求，同一候选`d905ed0776887f745eca85ce8c942dcd6bb1c282`自检13/13、独立测试13/13，Review完成且无阻塞问题，状态accepted/passed、taskAccepted:true。记录位于本地`output/executions/execution-Fs5URC/`，两方记录绑定同一validationId及候选标识，测试与Review使用不同目录。

可信候选命令诊断通过但taskAccepted:false，另有真实MXC诊断回归证明返工后提交变化、两方重新检查及历史问题显式关闭；模拟Review不冒充真实模型证据。无新增运行依赖、无用户data迁移，无网页修改，未重复付费联调。源码固定后再由独立测试与Review检查同一版本。
