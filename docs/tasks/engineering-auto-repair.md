# 工程草案自动修正与本地兜底

## 根因

工程阶段失败不是单点校验错误，而是“单次模型输出必须一次满足全部结构规则”的链路太脆：

- 模型常见格式偏差：`{id}`路由参数、`text`等无效ARIA别名、JSON代码块/尾部格式；
- 模型常见语义偏差：多个并行任务写同一文件、漏需求映射、未知引用、接口/页面ID问题；
- 失败后没有向模型反馈具体校验错误，只让用户再点一次“重试”，模型可能重复同类错误；
- 用户可用的恢复路径只有重试或复用旧回执，没有确定性兜底。

## 解决

1. **确定性规范化**：继续规范化`{param}`→`:param`；新增常见ARIA角色别名映射；工程模型解析前去除Markdown代码块包装。路径、文件范围、角色、DAG等安全规则不放宽。
2. **自动反馈修正一次**：首次出现`invalid_model_response`时，控制器把具体的校验说明（包括路由/页面/任务/共享文件位置）作为反馈发送给模型，自动再请求一次。反馈只含控制器文本；自动修正消耗下一次engineeringCalls和独立私有回执，最多一次。
3. **更具体的校验错误**：共享文件冲突包含文件名和两个任务ID；路径/角色错误包含接口/页面ID；漏覆盖包含缺失需求ID。便于模型修正，也便于页面和日志定位。
4. **显式本地兜底**：仍失败时，页面提供“改用本地规则生成架构与任务（不调用模型）”。动作`use_local_engineering`写入`engineeringFallback`，用确定性本地规划生成架构/任务/检查，重置下游并停在计划确认。task.md、architecture.md和plan.json标注本地规则来源；规格修订清除兜底。不是静默回退，也不授予执行许可。
5. 原有“重新校验保存的工程草案”保留，优先复用已保存回执，不额外调用模型。

## 验证

- `npm run check`：117脚本语法通过。
- `npm test`：703项，673通过、30跳过、0失败、0取消，99,368.0102ms。30项跳过为未启用真实MXC/显式真实Edge的既有集成项。
- 新增回归：
  - 无效JSON自动带反馈重试一次，第二次成功后架构/任务完成，engineeringCalls=2、两条回执；
  - 模型连续失败后显式本地兜底不新增模型调用，本地架构/任务/检查成功并停在计划确认，plan.json含engineeringFallback；
  - `{id}`路径、`text`等ARIA别名规范化；
  - 原有免费重校验、预算耗尽、凭据/传输/取消边界保持通过。
- 没有调用真实付费模型；未修改用户运行数据；没有把自动修正或本地兜底说成模型通过。

## 限制

- 自动修正只尝试一次且受engineeringCalls/超时预算约束；第二次仍失败时进入失败停点。
- 本地兜底生成的是确定性结构计划，不是模型工程方案；业务充分性仍须人工审阅和计划确认。
- 未验证真实DeepSeek对反馈的实际采纳率；真实模型质量另行验证。
- 本地兜底不改变固定参考Web执行、任意上传业务或编码完成的范围。
