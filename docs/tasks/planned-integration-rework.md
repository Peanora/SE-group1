# 将集成阻塞退回文件负责者

真实触发：v5 191 文件首次并行基准 `output/task-checks/notes-tags-qSaZDq`，BASE、NOTES、TAGS 已按当前局部门禁通过，两个独立候选实际并行且以真实 Git 合并。FINAL 的两轮代码均通过完整 HTTP/Edge，但 Review 指出 `public/notes.js` 的首次加载旧响应可覆盖新建条目。该文件仅 NOTES 可写，FINAL 只负责文档；第三次提案试图写 NOTES 文件被精确范围门禁拒绝，图最终失败，未交付。

这次共 15 个真实模型调用，233913 输入 / 28271 输出 token；金额未知。原失败、两次 Review（包括试图降级旧 blocking 的意见）、各候选与费用全部保留。程序没有允许通过降级或扩大 FINAL 文件范围来完成。不是所有任务图都已验收成功。

本轮目标：在同一已确认计划内，完整集成门禁发现精确且唯一上游文件负责者的 blocking 时，立即停止无权修改的 FINAL，将问题和真实失败源码交回负责者，连同其下游重新验证。首版只自动处理单负责者；同时涉及多个负责者时保存完整意见并停止，不能让每人修复时丢掉另一人的 blocking。当前图最多一次此类返工，各任务累计编码/Review 次数仍分别不超过原 3 次，全图 24 次与原绝对 20 分钟期限不重置。歧义、未知、取消、版本变化或预算不足则停在明确失败。

core 仅对原始执行对象、同一真实完整 manifest、当前授权及固定完整候选发放私有 rework 能力。JSON 中的 request 字段不能创建它。调度器要求所有当前 open blocking 同属唯一那个上游负责者；混入 FINAL 自有问题或其他负责者则保存全部问题并停止，不派发相互无权修复的任务。其余调用及所有原历史 blocking 不丢失，不能把已失败记录当成新通过。

task-store 新增同计划事务返工：指定确切根任务，由程序按已确认依赖计算下游闭包；旧尝试必须已确认停止且结算，取消/陈旧版本不得重开。保留原 completed 历史、回执及费用，重开任务换新 attempt/generation，旧重复 finish/publish 不再显示 current。幂等返工编号不能对应不同输入。已有计划、定义及写入范围不变。

图保存每任务全部尝试、返工理由、费用及旧结论；未受影响任务保持原版本历史，不产生“新提交通过”记录。负责者在保留完整集成源码的新独立 Git 候选修复，仍用自己的局部清单及全部原审查义务；FINAL 在新合并版本重新运行完整父清单与 Review。只有最终完整通过才封存整图并允许交付。

验证顺序：真实失败只读审计；有意义的 SQLite 陈旧/重复/预算反例与 controller/core 对照；冻结新组合后非作者测试及 Review；阻塞关闭后才做必要原生基准，不无变化重试收费请求。当前只为实施契约，尚未完成本轮接线或真实返工验收。
