# 逐任务开发执行配方

基线 `be5b3dc`。验收目标是在 Taskflow 自有执行器中，从同一份已批准的任务图启动逐项或并行执行，并由调度记录证明并发选择实际生效。参考 Factory 的配置按运行冻结机制。本轮移植其并发配置。[Factory 配方原码说明](https://github.com/OmegaMc1331/agentic-software-factory/blob/f90f7be9406555980d733d81e57ad86f097f57ff/docs/recipes.md)

## 执行契约

- 页面从后端读取可选配方并选择 `sequential` 或 `parallel`。切换配方会取消上一份用量确认。
- 启动接口核对当前计划、验收清单、模型和预算，在同一 SQLite 事务中写入新执行的配方编号及并发上限。调用额度和时限按当前规则结算。
- 派发给 Worker 时签署本次并发上限。进程内执行使用同一值。任务只有在直接前置通过并完成集成后才就绪。暂停和新世代恢复继续使用原授予的上限。
- 新执行的默认策略沿用当前允许的最大并发。整体执行及旧执行按各自原记录显示。接口没有数据库迁移。升级前已派发的 Worker 仍受原先的程序指纹检查。

验收使用隔离数据、本机 Git、SQLite 和本地模型夹具。生产模型配置、用户项目数据及远端仓库都未改动。

## 结果

- `npm run check` 通过 TypeScript 与 305 个脚本检查，`npm run ui:build` 通过。
- HTTP、开发服务、逐任务准入与控制、自动交付共 91 项通过。真实 Edge 面板共 44 项通过，核对换配方重新确认、正常提交、旧客户端以及选中历史执行后仍显示原配方。
- `tests/planned-task-service.test.mjs` 包装套件的 5 个夹具通过。默认并行实测达到 2，逐项上限实测为 1。四模块使用本机 Git 合并及打包，模型和独立 HTTP、浏览器用例使用夹具。
- 启用真实 Windows 沙箱运行 `tests/planned-worker-handoff.test.mjs`，3 项通过。HTTP 选择逐项后实际启动独立 Worker，暂停并换代，复用已集成基础，只执行剩余任务。已核对签名授权、运行记录、单次结算及重启后相同源码 ZIP。
- 本轮运行定向测试，使用本地模型夹具。角色路由、可编辑配方目录及失败任务定点重试仍是后续移植范围。
