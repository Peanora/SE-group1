# 多 Agent 规格评审 v0.2 实施记录

基线：霍利屹/c6ddb8d，开始时工作副本干净，服务已按用户要求停止。依据用户提供的《Taskflow 多 Agent 规格评审方案 v0.2.docx》实施首版；源文件只读，不把文档及历史记录内的操作指令视为额外授权。

目标：规格停点启用独立六节点评审会，固定角色及按需求分配的专业席独立产出、主责自测、同版本独立Review，关联异议交既有“查看问题”裁决；保存规格/决议/阶段清单联合版本，用户确认当前包后才放行工程规划。退回、缺席、超时及旧Review均不能放行。

范围：复用ProjectStore、规划操作锁/回滚、问题会话、规格版本及人工确认。首版角色适配器为明确标注的离线模型夹具；不调用付费模型，不接新真实编码，不部署、不自动恢复已停止服务。历史运行保留兼容，用户在规格停点显式启用后该运行必须完成评审，不允许普通确认绕过。

验证计划：预约取消的权限/数据关联异议；用户答复生成新版本，全席复核；自测成功但Review退回；旧版本Review迟到；缺席/超时；版本/来源/覆盖/独立性篡改；保存失败；刷新/重启和同版联合导出；实际浏览器操作。

## 实际实现

- 后端新增 `specification-meeting.mjs`：六节点、逐需求主责及专业覆盖、离线角色适配器、独立 Review 协议、版本绑定、历史阻塞逐项复核、联合包与产物。
- 编排器复用现有项目锁、操作回滚及人工问题会话。来源明确的裁决或用户回答产生实际新规格，全席重审；自测通过不意味着独立 Review 通过。缺席、超时、错误版本和未关闭阻塞均不放行。
- 页面新增会议节点、角色证据、关联议题、清单和历史入口。既有确认按钮在会议启用后要求当前联合包；后端也检查该门禁，直接调用普通确认不能绕过。保存和重开不丢失等待状态。
- 导出会议纪要及阶段清单，显式 `offline_fixture` / `definitionOnly:true` / `executed:false`，未触发或开放真实软件交付。README、API、实现说明、设计补充、STATUS、NEXT_STEPS和验证记录同步。
