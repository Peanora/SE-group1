# 开发任务模拟编排

基线：main / eb78c55，开始时工作副本干净。当前用户授权本轮开发及必要免费本地验证；历史授权和暂停不自动沿用。

目标：保留规划流程，从双确认的当前计划冻结独立模拟运行，按DAG、写入范围、并发上限及人工门禁推进任务。记录由后端保存，模拟结果不能进入真实源码验收。

范围：复用ProjectStore原子JSON保存、planning-review版本门禁、任务图和文件校验；新增模拟执行器/调度服务、HTTP接口和任务图交互。现有事务任务库要求可信真实验收清单，不适合将模拟结果灌入，首版不接该库。

验收：A→[B,C]→D→E，D人工确认；失败分支、重试、暂停、刷新/重启、版本隔离、非法图/共享写冲突、越权完成及真实源码门禁隔离。使用临时数据和可控模拟执行器，不调用模型，不推送或部署。

实现：`lib/simulated-tasks.mjs`提供可替换的模拟执行接口、项目内串行控制、并发DAG派发、独立模拟快照和保存优先的状态发布。`lib/task-write-validation.mjs`复用现有精确路径校验，采用原工程计划相同的共享写依赖规则；工程模型计划另走原有alignment校验，没有修改工程校验器及其历史策略hash。`server.mjs`新增模拟HTTP/导出接口，`Orchestrator.assertProjectAvailable`连接活动模拟门禁，保护规划修订及原有需求检查点。JSON写入复用ProjectStore，不改数据库和真实源码验收流程。

页面：复用原任务图及其焦点/滚动处理，独立模拟面板按650ms轮询已保存状态，展示当前/历史运行、失败原因、尝试、人工依据和状态历史。状态由后端结果驱动。示例DAG作为明确标注的确定性夹具，既不冒充真实PM调用，也不作为真实开发结果。

实际验证（2026-11-16）：

- `npm run check`：105脚本语法通过。
- `npm run simulation:test`：90/90通过，失败/取消/跳过全0。覆盖A→[B,C]→D人工确认→E、失败支路、保留成功重试、阶段边界暂停、非法/重复/过期人工完成、刷新及新Store回读、重启中断、新计划/新需求隔离、非法图/共享写/大小写冲突、写入先于派发、保存失败停止派发、模型工程计划兼容及真实源码门禁隔离。还运行原工程规划、规划确认、项目操作、HTTP、存储、需求变更相关回归。
- 实际Edge桌面1440×1000及窄屏390×844：页面人工确认计划→启动模拟→B失败/C完成→暂停/继续→重试B→刷新→D填写依据确认→E模拟完成；A/C仅执行一次，B两次，无页面/控制台错误，无窄屏横向溢出。截图在`output/simulation-verification/`，测试输出在`output/simulation-checks.log`，均为本地产物，不提交。
- `npm run simulation:demo`实际运行，生成独立`output/simulation-demo-data`；规划停在awaiting_review，仍需页面人工确认计划。没有启动常驻新服务或更改默认用户数据。

验证过程保留事实：初次测试存在临时目录清理先于新服务shutdown、测试夹具未等审阅保存结束、工程夹具缺必需页面三项测试准备问题，均修正后复验；没有放宽生产校验或删除断言。它们不构成90项通过前已经完成的结论。

未运行：全仓库完整测试、真实MXC编码及业务验收、真实付费PM/Review模型、未涉及浏览器场景的完整产品回归、非作者独立验收。此前部署轮的完整测试有2项失败及30项跳过，本轮90项相关通过不能覆盖或消除那份历史结论。

限制：单机单控制器JSON与轮询，执行器仅模拟；外部Worker可靠恢复、通用编码、团队身份和新真实验收均未实现。人工依据是本地自由文本记录，没有身份签名。普通规划目录/通配建议须先人工明确成允许精确文件，否则模拟启动被明确拒绝。活动期间禁止修改计划；中断/失败旧版本只读，不把旧完成移入新计划。没有强制完成接口；模拟记录永远不赋予真实源码交付资格。

本地分支`codex/simulated-task-orchestration`，以一次目的明确的本地提交保存；没有推送或部署，也未重启原4317服务。演示命令和操作见[SIMULATION](../SIMULATION.md)，本轮新能力验证依赖临时测试服务，不把旧进程当新版启动证据。
