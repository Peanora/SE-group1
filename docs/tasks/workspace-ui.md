# 工作区收拢与当前视口失败反馈

## 目标与基线

基线`main/171aaa6`，开始时工作副本干净。用户反馈界面操作分散、频繁跨页面位置跳转、顶部失败提示在下方操作时看不见。本轮验收目标：通过固定工作区导航和就地编辑，让用户知道当前项目、当前阶段和下一步；下方操作或后台阶段失败时，原因与恢复入口在当前视口可见，轮询不抢走输入焦点。

用户明确要求之后先不提交。本轮仅保留本地未提交修改，不创建提交或推送，不重启现有服务，不修改用户数据、密钥、后端执行范围和审批/计费规则。

## 设计

四个固定工作面：规划与确认、开发任务、需求与功能、代码与验收。保留每个模块的同一份真实DOM，切换只改变展示；当前项目、运行、阶段和下一步常驻。工作流图、技术预算完整说明和历史等辅助内容收拢，当前需要处理的业务表单与简明计费提示仍可见。

任务编辑在原任务图旁的原生对话框中打开，将既有审阅表单临时移入，关闭后返回任务图并保留草稿、选择和阅读位置。新增功能表单在完整正文之前，功能模式把完整正文归入可展开详情，加入草稿后就地继续保存与应用，不再反向聚焦正文。

沿用蓝白产品方向并提高可读性：白色`#ffffff`、页面浅灰蓝`#f3f6fb`、深蓝正文`#203451`、操作蓝`#315deb`、成功绿`#16846a`、失败红`#b5403b`。正文采用当前系统中文无衬线字体，常用表单与提示提升至13–14px，标题层次服务项目/工作面/具体任务。布局以左对齐、明确的活动工作面和少量分隔组织，不增加装饰性卡片与动画。

通知持久、可关闭、绑定项目/运行，并在当前视口展示；后台失败从真实阶段状态派生，用户主动点击才定位恢复位置。对话框内的通知也必须可见。模型/代码执行、模拟与规划状态保持真实含义。

## 写入边界

- 根：整体HTML、app接线、工作面控制器与统一布局样式、文档。
- 通知Agent：独立通知模块/回归、模拟局部错误及相关浏览器回归。
- 需求流程Agent：需求变更模块及面板回归。
- 浏览器Agent：整体与现有导航回归，不修改前两位Agent独占文件。

## 实际实现

`index.html`、`workspace.css`和`workspace-layout.js`提供四工作面、常驻上下文、标签键盘操作、会话内视图/阅读位置恢复及同DOM任务侧边对话框；`app.js`连接原有操作并提供明确的下一步和错误定位，不自动切走正在填写的工作面。需求模块把功能表单置前，完整正文按需展开，保存与状态就近呈现；模式往返保留草稿。通知模块复用原错误DOM，按项目/运行处理持久通知、上下文变化和已知网络异常；执行与模拟模块只从有效响应的当前失败事实发回调，拒绝迟到/ABA，不把动作接受当任务成功。模拟另保留操作旁的局部错误。

首轮浏览器验证发现错误浮层挡住恢复按钮，改为工作台独立底部区域，恢复按钮可直接点击。首冻结清单`2B9AE1A5…`为20份生产/测试文件，125脚本语法通过，完整测试754项（724通过、30跳过）。独立审查仍BLOCK：390×667展开长错误后，通知关闭/定位落在视口外，工作面只剩2px；不是用自动滚动后能点击就算通过。

最终修复把通知设为有整体高度上限的grid，正文独立滚动，标题与动作始终留在区域内；短屏错误状态压缩重复的头部说明，保留项目/运行、导航和预算入口。局部长错误也限制高度。新增390×667/844真实API长错误回归，普通指针通过坐标和`elementFromPoint`验证展开、定位、再次保存及关闭；正文可滚、草稿保留、外层main/body不被自动滚动、模型调用0。
