# 四项交付验收接续

基线为原工作区 `48ac170`。原有团队交付计划改动保留。本轮使用独立工作区、隔离业务数据和本机端口。

- 预约固定扩展清单、Git 候选、独立 HTTP、双视口 Edge、同版 Review 及正式 ZIP。未解决的阻塞意见与失败回执保留。
- 自动清单沿用受控 DSL、覆盖和依赖检查，并记录真实模型生成与确认的版本。需在复杂案例通过正常接口验证。
- 演进依次完成字段、权限、流程三个版本，使用旧业务数据、真实编码和独立审查。每次保留激活前后旧数据证据与用量。
- 跨版本 Worker 复用原事务预留、签名授权、预算和真实运行器。Worker 可在 API 进程退出后核对同一批准、数据来源与旧发布，并在自己的数据目录中生成独立迁移副本。收尾由重启后的 API 核对签名、原始迁移回执与完整验收。旧状态无法核对时保留原预留。


## 持久演进验证

实际 MXC、Edge、独立 Git 与 SQLite 共 23 项相关回归通过，275 个已有脚本和本轮新增脚本合计 279 项语法检查通过。完整真实进程测试通过 HTTP 启用旧版并写入两条数据，启动跨版本持久 Worker，在编码回复挂起时正常关闭 API，再强制终止重开的 API。最后一个 API 接回原 Worker，使用四份迁移副本完成双视口和验收，同版只结算一次编码与一次审查。激活后读回两条旧记录及新默认字段。重开取回同一 ZIP，原数据库字节一致。修改一份验证用迁移产物会拒绝交付，恢复原字节并重开后再次得到同一 ZIP。测试模型为本机夹具。
