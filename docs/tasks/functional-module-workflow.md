# 按功能模块生成与执行

本轮基线 `f4a1e92`。验收目标是从已确认规格产出每项可独立验收的功能模块，并在画布、计划版本以及可启动的执行记录中保留同一组模块和直接依赖。功能板块用于组织模块，跨板块执行由模块间的直接依赖决定。

改动覆盖本地规则与工程模型规划、计划修订和交付投影、按图执行的默认入口、横向泳道及模块详情。已有已确认版本继续按原快照读取。检查图上的单模块选择、输入输出、检查点、换位与拖线；用独立测试空间验证前一板块仍有任务运行时，下游板块可以接手已完成模块的产出，汇合点等待全部直接输入。

## 可复现的输入和结果

在新项目导入[校园场地预约需求](../../examples/venue-module-workflow.md)，选择本地规则并确认规格。时段目录和预约配额是两个独立模块。时段日历只读取时段目录。预约申请同时读取时段目录和预约配额，取消预约读取已有申请。全局验收汇合时段日历与取消预约的结果。普通规则计划可供审阅和模拟，正式源码执行另须工程契约。

工程模型的模块信息随新草案校验、计划哈希、审批和产物写入。每条边来自任务的直接前置，板块组织不制造依赖。对照的参考实现也在寻找就绪节点时单独处理阶段容器和真实入边。[参考项目的就绪判断](https://github.com/ycwang-April/SE-TeamPrjoect/blob/main/workflow-orchestrator/src/core/twin-graph.ts#L88)

## 验收范围

- 真正执行前需要已批准的逐模块 HTTP 和浏览器验收清单。当前执行器接受 2 至 8 个模块、一个负责 `src/app.mjs` 的基础入口及一个最终集成点。设计与导出可保留超出这些条件的图。
- 以本机 Git、SQLite 和隔离模型、验收响应验证逐节点派发。一条分支的候选通过并集成时，依赖它的其他板块模块开始执行；另一分支的失败阻止最终汇合领取任务。已批准版本、真实派发与源码资格分别核对。
- 实际浏览器覆盖一模块一卡、详情中的执行步骤、同列换位、跨板块真实连线、修订后重新确认、旧计划增加模块名和板块，以及桌面与窄屏导航。[本轮验证记录](../VERIFICATION.md#2026-11-27-按功能模块生成与跨板块执行)

独立工程演示使用校园场地预约的测试模型响应，从真实 HTTP 规划与确认入口生成首版。新进程重新打开磁盘后，7 个模块、4 个板块和 8 条直接依赖与验收计划快照一致。预约申请读取时段目录与配额判定，取消预约读取已生成的预约，交付检查点等待时段日历和取消预约。截图位于本地 `output/playwright/functional-module-workflow-1440.png` 与 `functional-module-workflow-390.png`。这份演示处于工程计划确认状态，通过模型替身生成，未执行付费编码。
