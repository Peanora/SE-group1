# 首个受控编码任务执行入口

日期：2026 年 11 月 14 日。基准：`main@b133109`，开始时工作区干净。

## 本轮目标与范围

用一个固定、已明确验收的图书借阅模块任务验证程序化编码入口：模型提出受限文件改动，平台实际写入独立工作区，固定验证器在受限环境执行候选代码，保存真实命令结果、差异及版本。同步实现总时长、模型调用、输出大小预算与停止。现有需求规划、HTTP 与前端行为保持可用。

本轮先提供独立可调用模块与命令行验证入口，不将现有规划运行的成功解释为软件完成；暂不接动态任务领取、多 Agent 集成、完整业务生成、自动发布。

## 最小契约

- 任务、初始代码、可写文件和验证入口由平台登记；模型不提供宿主路径、命令、环境变量或验收文件。
- 每次尝试记录任务/规格/计划内容标识、工作区、基础版本、候选版本、调用与命令记录。执行完成与独立软件验收分开。
- 模型凭证只留在控制进程，目标代码不继承服务端环境。
- 验证环境预检不通过时拒绝执行目标代码。独立目录不当作系统隔离。
- 总时长、调用次数、响应/输出/变更大小设上限；停止和超时须等待受管进程退出确认，无法确认时保留待协调状态。

## 验收与版本门禁

1. 实际文件编辑及版本差异可复核，固定业务检查真实执行并记录结果。
2. 语法或业务错误产生真实失败；模型口头成功不能放行。
3. 越界写入、修改验收、超大输出、超时和停止有回归测试。
4. 环境缺少保护时明确失败，不退回无保护的宿主执行。
5. 主 Agent 自检后固定候选提交，由测试与 Review 子 Agent 检查同一版本；修复形成新提交复验。

## 验证记录

主Agent自检：`npm run check`24个脚本通过；显式开启真实MXC检查的`npm test`48/48通过、无跳过。可信候选诊断通过。真实模型首次因规格歧义达到2次预算失败；澄清空数组及空白规则、扩充3个边界检查后，新执行1次模型请求、13/13检查通过。旧失败及候选版本保留。

隔离与停止有真实证据：外部自建sentinel读写拒绝、网络拒绝、代码只读、中文stdin、ESM加载及停止后的进程心跳不再增长。未改浏览器，无新增依赖，未运行完整全栈业务或双Agent产品验收。

候选源码提交后进行同版本独立测试及Review；结论在完成后补充。工作分支为`codex/execution-foundation`，未推送或部署。
