# 工作流工作台重构

基线为 `codex/workspace-ui/88fea37`。本轮围绕一次项目运行重新设计主界面，验收目标是从首页流程图找到当前人工操作，再从运行复盘定位规划阶段或开发尝试及其证据。

首页采用浅色流程画布、深色应用栏、按阶段组织的节点和当前操作区。需求、规格、任务、执行验收和复盘提供各自的阅读空间。设计参考 [SE-TeamPrjoect](https://github.com/ycwang-April/SE-TeamPrjoect) 的分阶段工作台与节点检查方式。

运行视图按项目和运行绑定既有记录。规划、审批与开发使用各自的事件来源和版本。复盘展示当前可读取的记录，缺少时间、执行记录或版本绑定时说明可用范围。启动、确认、重试、收费授权和交付沿用服务端动作。

导航使用项目、运行和工作面参数。刷新后回到所选任务，查看历史记录也有独立的运行归属。旧版规划只展示其四个实际阶段，旧版审阅通过后可打开交接文档。

## 验证

- `npm run ui:build` 与 `npm run check` 通过，包含 TypeScript 和 308 个脚本语法检查。
- 工作台、复盘、旧版流程、任务编排、模拟调度、团队登录、项目删除、自动交付停止、固定参考门禁和计划修订等定向回归合计 51 项通过，包含团队套件复测。2 项需要单独启用 Windows 隔离执行的测试跳过。
- 开发中的全仓运行记录为 1401 项通过、13 项失败、5 项取消、92 项跳过。更新旧界面定位和异步导航断言后，相关浏览器回归通过。初次全仓运行中其余失败与取消来自四个后端套件。四个套件降为逐文件运行后 58 项通过、4 项跳过。最终提交完成了上述定向复测。
- 在 1440px 和 390px 的真实 Edge 中运行校园场地预约示例。规划停在计划确认，6 个任务和 25 条复盘记录可查。从「仅异常」进入拆解任务失败的阶段，可看到同一运行的重试过程。复盘的候选定位另使用含历史执行及多个提交的夹具验证。
- 本轮使用本地规则和离线测试夹具。预览记录到计划确认，前端交互测试核对执行证据及交付门禁。付费模型和真实生成业务的全流程交付未在本轮运行。
