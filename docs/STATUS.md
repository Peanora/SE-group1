# 当前实现与开发交接

更新日期：2026年11月14日。

## 当前能力

浏览器工作台仍是需求规划与文档编排原型：支持MD/TXT/DOCX正文导入、需求快照、固定工作流、任务依赖图、阶段边界暂停、失败重试、人工审阅、文档预览及下载。模型只在规格阶段使用，后续架构、任务和检查主要采用确定性规则，生成的开发任务仍为待开发。

网页已新增workflowVersion=2的规格/计划双确认、问题逐项答复、表单修订、驳回及完整历史。确认必须匹配当前版本；规格确认前不拆任务，旧确认及下游结果在修订后失效。每次运行冻结原始需求，历史导出不会读取后续的新需求；旧版记录仍按原义查看/导出。草稿和选中项目/运行在标签会话保留。

新增独立受控编码试验入口：固定图书借阅模块任务 → 模型文件建议 → 独立工作区实际修改 → Git候选提交 → Windows MXC受限执行 → 平台固定业务检查。已用真实DeepSeek请求完成一次代码修改，13项检查通过。检查期间目标源文件只读，工作区外读写与网络拒绝，进程输出、时长和模型请求均有预算及停止处理。

现已在命令入口接入同版本独立测试服务与Review模型：Git候选固定后，两份副本分别检查，Review不读取测试结论；只有固定检查通过且Review阻塞问题关闭才产生accepted/passed。修复生成新提交，两方均重新检查；候选变化、缺失结论、服务错误和取消都不得放行。固定测试服务仍不等于测试模型自主生成用例。

该试验尚未接入浏览器规划任务图，不包含任意仓库、依赖安装、完整全栈生成或软件集成交付。无Review的兼容调用仅为executed/not_reviewed，可信候选诊断为diagnostic_passed/taskAccepted:false。

## 设计与使用入口

协作设计以用户2026年11月10日指定的[新版设计](DESIGN.md)为依据，原始Word在根目录保存。[产品需求](PRODUCT_REQUIREMENTS.md)和[实现流程](ROADMAP.md)继续作为目标；当前浏览器行为见[实现说明](PROTOTYPE_DESIGN.md)，编码试验契约见[API](API.md)。

`npm run execution:check -- --fixture`验证可信固定候选和诊断Review，不调用模型；`--model`调用本地LLM配置，编码与Review各最多2次请求、共享180秒，并产生正常用量。两者都要求已预检通过的Windows MXC环境，缺少保护时拒绝执行。执行器路径仅在本地.env配置，执行与acceptance记录在被忽略的output/executions/保留。
